# 在另一台电脑启动服务器

## 复制与启动

1. 把完整源码包复制到新电脑并解压，保留目录结构；不需要旧电脑的绝对路径、开发工具、GitHub 账号或令牌。
2. 安装 Node.js 22.8+，无需 npm install。Windows 双击「启动染域.bat」；macOS / Linux 运行 `sh start.sh`。也可在项目目录运行 `node server.js`。
3. 便携运行可把对应系统的 Node 可执行文件放到 `runtime/node.exe`（Windows）或 `runtime/node`（macOS / Linux，需可执行权限），启动脚本会优先使用它。源码包不附带 Node 运行时。
4. 在主机打开 `http://localhost:3000`。同一网络的朋友使用启动窗口显示的局域网地址。Windows 防火墙需允许该程序在专用网络通信。

服务器电脑需保持运行、联网，避免休眠。关闭启动窗口就会停止服务。房间保存在内存中，重启或迁移主机不会保留对局；浏览器身份按访问地址保存，切换域名或电脑地址后不会自动继承原席位。

## 可选配置

无需配置即可按原来的局域网方式游玩。需要改端口或准备代理时，将 `server.config.example.json` 复制为同目录的 `server.config.json`，例如：

```json
{
  "host": "0.0.0.0",
  "port": 3000,
  "publicUrl": ""
}
```

- `host`：默认监听全部 IPv4 网卡。仅在本机代理转发时可用 `127.0.0.1`；此时局域网设备无法直接连接。
- `port`：1–65535，默认 3000。端口被占用时启动窗口会提示，可换一个端口再启动。
- `publicUrl`：以后有了穿透或反向代理入口，再填完整的 `https://你的域名`。留空表示没有指定外网分享地址。只支持根地址，不含子路径、参数、账号或密码。

环境变量 `HOST`、`PORT`、`PUBLIC_URL` 优先于文件；修改配置后重启服务生效。`server.config.json` 与 `runtime/` 不提交到 Git。更换电脑时可复制自己的配置，但需要检查 IP、端口和域名是否仍适用。

## 已适配的代理逻辑

代码支持 HTTP 与 HTTPS 页面请求。代理需要把网站根路径下的所有页面和 `/api/*` 一起转发到同一个 Node 服务，保留原始 Host；若代理改写 Host，则把对外地址填入 `publicUrl`。服务端仍会拒绝其他站点的跨源写入，不信任任意客户端提供的 `X-Forwarded-*` 头。不需要开启 CORS。

分享链接自带六位房间号。通过局域网或外网地址访问时，分享使用当前访问地址；通过 localhost 访问时，优先使用配置的 publicUrl，否则提供本机局域网地址。请让朋友始终使用同一个地址。

SSE 推送已提供禁止缓存、禁止缓冲的响应头，代理也应关闭 `/api/events` 的缓存和响应缓冲，并允许持续连接（建议读取超时至少 60 秒）。每 5 秒有心跳；SSE 不可用时客户端自动使用 HTTP 轮询，重连后不会自动重复提交行动。

**填写 publicUrl 仅配置校验与分享链接，不会创建外网入口、申请域名、安装穿透工具或开放路由器端口。** 真正接入外网时，需另外配置穿透服务，把入口转发到这台电脑的 `http://127.0.0.1:3000`（或自行设置的端口）。本次没有启动任何穿透服务。


## 锚点积分存档迁移

房间仍保存在内存中，关闭服务会结束当前对局；积分和锚点收藏单独保存到 `data/profiles.json`。若设置了 CHROMA_DATA_DIR，则在该目录内保存。一个数据目录只供一个游戏服务进程使用。

迁移到新电脑时先停止旧服务，另外复制自己的 data 文件夹至新服务器，再启动游戏。保留相同的访问域名及浏览器身份可继续使用原积分；仅搬源码包不会带上私人存档。不要把 data 文件夹上传公开仓库或放进公开下载包。备份时在服务停止后复制完整目录；损坏的存档会报错，不会自动清零覆盖。
